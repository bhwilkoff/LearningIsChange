Civic · Live

Yes on 4A: Tell the Story of Our Schools

A volunteer-built storytelling toolkit for supporters of the Littleton Public Schools mill levy override on the November 2026 ballot. Story prompts by who you are, a Share Studio that hands your words to each network with the least friction the platform allows, a share-card generator, a cost calculator that shows the county assessor's actual math with every source linked, and a team playbook. Every fact links to where it came from, because a campaign like this should be able to show its work.

Data & Simulation

Harvey Cup Draft Assistant

A fantasy-football projection engine, draft simulator, and live advisor that runs inside the Yahoo draft room. Blends four sources' stat projections, scores them under the league's own rules, values against a simulated replacement level, and picks a strategy by running thousands of drafts and seasons scored on title odds. Every clever rule was tested, and most of them lost. Twenty-six mock drafts and two real ones, every pick graded against the advice.

The App Template

One open-source starter, written so Claude Code can use it, for building a shared-core app with native shells for phones, tablets, desktops, TVs, and the web, with feature parity. It grew one screen at a time (Dual, Tri, Quad, Quint) and is now a single rolling Universal App Template, with the store-submission pipelines and device harnesses from the live apps vendored in.

Infrastructure & Platform

Everything I run is a static site on GitHub Pages with no servers. These are the systems that make that possible.

Platform

Learning is Change CMS

Learning is Change itself: twenty years of WordPress moved to JSON and static files, with every URL, comment, and feed kept working. LiC Admin, the editor I write in now, is a small app that talks to GitHub and renders the whole site in about five seconds, with no backend at all.

Infrastructure

CI Fleet & Device Harnesses

Archive Watch's content pipeline is 30+ scheduled GitHub Actions workflows that discover titles, audit rights, check that every file plays, and publish one catalog to every app. Keeping that fleet honest meant building the compute/apply lock split, budgets that publish, a self-healing sweeper, a health auditor where a red X is reserved for broken, and a product-health dashboard that reads every store's metrics. On the device side: scenario harnesses that drive real Apple TVs, Pixels, Fire TVs, and Rokus and read the screen back with OCR, so a feature ships when it has been seen working. All of it is documented in the Universal App Template.

How I decide what to build

Every project starts with a real need, usually mine. I build tools that solve one specific problem for students, for teachers, or for me. I build most of them with Claude, and I still decide what is worth building and whether it is done. I want each one to work, to be open, and to be something someone else can learn from or build on.
